# Frequently Asked Questions

## General

### What is QProcessor?

QProcessor (CELLULARIS) is a quantum-inspired cellular computation framework.
It combines biological metaphors (cells, differentiation, mitosis) with
quantum-inspired temporal computing and hyperfractal precision.

### What makes it different from a conventional framework?

Three things:

1. **Time is the computation.** Temporal gates operate on timers; the
   echo cascade achieves picosecond precision from microsecond hardware.
2. **Cells are self-describing.** Every computational unit carries a shard
   with complete provenance — identity, lineage, operations, receipts.
3. **The network sheaf** models the global network from public observation
   planes and reconstructs it from the residual via active inference.

## Temporal Precision

### How can software achieve picosecond precision?

A timer event produces a cascade of self-similar echoes at geometrically
decreasing intervals. Analyzing the interference pattern and computing
derivatives across recursion depths resolves features below the hardware
resolution: `Δt_effective = Δt_base × α^N`. With α=0.1 and N=6, a 1μs base
resolution becomes 1ps. See `docs/spec/ECHO.md`.

### Is this real quantum computing?

No. This is a quantum-*inspired* classical system. The gates, phases, and
measurement probabilities follow quantum analogies, but everything runs on
classical hardware with timers.

## Cellular AI

### What is the difference between Cellular AI and a neural network?

A neural network is a static graph of weights. Cellular AI is a population
of self-organizing cells that differentiate into specialized roles,
replicate through mitosis, self-repair on failure, and record complete
provenance for every decision.

### How does the AI learn?

The Frontier Cellular AI (`src/frontier_cellular_ai.py`) absorbs
`LearningExperience` records, tracks per-cell success rates, tunes temporal
parameters, and discovers new capabilities from recurring patterns.

## Network Sheaf

### Does the network sheaf scan the internet?

No. That is the central design point: because the network is sparse and
structured, the model infers rather than measures. It reconstructs the
network from a small fraction of observations and uses active inference to
decide what to measure next. See `docs/architecture/SheafFusion.md`.

### What data sources does it use?

Only public channels: BGP route collectors (RouteViews, RIPE RIS), DNS,
Certificate Transparency logs, RIPE Atlas probes, GNSS timing, and public
blockchain headers. Adapters are pluggable and the core never depends on
any single channel.

### Can it see private networks?

No. The model covers the *observable* network. Dark address space and
private infrastructure are outside the information horizon.

## Development

### What is Documentation-Driven Development (D³)?

Specifications in `docs/spec/` are the single source of truth. Every
function is specified before implementation, code must match the spec
exactly, and the reviewer system verifies compliance. See
`DEVELOPMENT_SYSTEM.md`.

### How do I run the tests?

```bash
bash scripts/test.sh           # unit tests
bash scripts/checkpoint.sh     # sequential milestone tests
bash scripts/review.sh         # full reviewer system
bash scripts/build.sh          # everything
```

### What is the difference between src/ and src_realtime/?

`src/` is the reference implementation. `src_realtime/` mirrors it with
nanosecond-anchored timing using `time.perf_counter_ns()` for live
measurement rather than simulation.

### Where is the API reference?

`docs/api/`, generated by `python3 scripts/generate_api_docs.py`.
